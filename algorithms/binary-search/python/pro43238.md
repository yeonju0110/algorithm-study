## 💡 풀이 과정 (생각의 흐름)

### 1단계: 문제 분석 및 접근법 고민

- n이 최대 10억, times 원소도 최대 10억 → 브루트포스는 불가능
- "T분 안에 n명을 심사할 수 있는가?"를 판단 함수로 사용

**의사코드:**
```
1. 탐색 범위 설정: start = 1, end = max(times) * n
2. 이진 탐색 시작:
   - mid 시간에 심사 가능한 인원 계산
   - 각 심사대에서 mid // time 명씩 처리 가능
   - 총 처리 가능 인원이 n명 이상이면 → 더 짧은 시간 탐색
   - n명 미만이면 → 더 긴 시간 필요
3. 조건을 만족하는 최솟값 반환
```

**answer 업데이트 타이밍**
- `person >= n`일 때 answer를 업데이트하는 이유:
- 조건을 만족하는 가장 작은 값을 찾기 위해
- 더 작은 값이 있을 수 있으므로 계속 탐색 (end = mid - 1)


---

## 💻 최종 코드

```python
def solution(n, times):
    answer = 0
    
    start = 0  # 실제로는 1부터 시작해도 되지만, 0으로 해도 로직상 문제 없음
    end = max(times) * n  # 최악의 경우: 가장 느린 심사대에서 모두 처리
    
    while start <= end:
        mid = (start + end) // 2  # 중간 시간값
        
        # mid 시간 동안 처리 가능한 총 인원 계산
        person = 0
        for time in times:
            person += mid // time  # 각 심사대에서 처리 가능한 인원
        
        # n명 이상 처리 가능하면 더 짧은 시간 탐색
        if person >= n:
            answer = mid  # 현재 시간 저장 (최솟값 후보)
            end = mid - 1
        else:  # n명 미만이면 더 긴 시간 필요
            start = mid + 1 
    
    return answer
```

### 📈 복잡도 분석

#### 시간 복잡도:
- **O(M × log(N × T))**
  - M: 심사관 수 (최대 100,000)
  - N: 대기 인원 (최대 10억)
  - T: 최대 심사 시간 (최대 10억)
  - 이진 탐색 범위: max(times) × n ≈ 10^18
  - 이진 탐색 반복 횟수: log₂(10^18) ≈ 60회
  - 매 반복마다 심사관 수만큼 순회: O(M)
  - **총 시간복잡도: 100,000 × 60 = 6,000,000 연산** (충분히 빠름)

#### 공간 복잡도:
- **O(1)** 
  - 입력 배열 외 추가 공간 사용 없음
  - 몇 개의 변수(start, end, mid, person, answer)만 사용

#### 실제 수치 (최악의 경우)
- n = 1,000,000,000명, times = [1,000,000,000]
- 탐색 범위: 1 ~ 10^18
- 이진 탐색 반복: 약 60회
- 총 연산: 60회 (심사관 1명이므로) → **매우 효율적**
