## ⚙️ 사용한 알고리즘
- **BFS (너비 우선 탐색)**: 가까운 단어부터 탐색하여 최단 변환 횟수 보장
- **문자열 비교**: 한 글자만 다른 단어인지 판별

---

## 💡 풀이 과정 (생각의 흐름)

### 1단계: 문제 분석

**핵심 결정 사항 파악**
> `begin`에서 `target`까지 **한 번에 한 글자씩만 바꾸면서**, `words` 안의 단어로만 이동할 때 **최소 변환 횟수** 계산

**조기 종료 조건 파악**
```
1. target이 words에 없으면 → 0 반환 (변환 불가)
2. BFS 탐색 중 target을 찾으면 → 즉시 반환 (최단 보장)
3. 큐가 빌 때까지 target을 못 찾으면 → 0 반환
```

**시간복잡도 검증**
```
단어 수: 최대 50개
각 단어 비교 시 글자 수: 최대 10개
BFS: 각 단어는 visited로 1번만 처리

→ O(N² × L) = 50 × 50 × 10 = 25,000 → BFS로 충분히 가능
```

---

### 2단계: 알고리즘 설계

**BFS를 선택한 이유**

한 글자씩 바꾸는 과정이 **그래프의 간선**이고, 최단 경로를 구하는 문제이므로 BFS가 적합하다.

```
상태: 현재 단어의 인덱스 + 현재까지의 단계 수
전이: words 중 한 글자만 다른 단어로 이동
목표: target에 도달하는 최소 단계 수
```

**BFS 설계**

- `begin`은 words에 없을 수 있으므로 큐에 직접 넣지 않음
- 대신 BFS 시작 전, `begin`에서 한 글자만 다른 words의 단어들을 **단계 1**로 큐에 삽입
- 큐 원소: `int[] {단계수, 단어인덱스}`
- visited 배열로 중복 방문 방지

**핵심 BFS 흐름 예시**
```
begin="hit", words=["hot","dot","dog","lot","log","cog"]

초기 큐:
[(1, hot)]  ← hit과 한 글자 차이

hot(1단계) 꺼내기 → dot, lot 추가:
[(2, dot), (2, lot)]

dot(2단계) 꺼내기 → dog 추가 (lot은 visited):
[(2, lot), (3, dog)]

lot(2단계) 꺼내기 → log 추가:
[(3, dog), (3, log)]

dog(3단계) 꺼내기 → cog 추가:
[(3, log), (4, cog)]

cog(4단계) 꺼내기 → target! → return 4 🎯
```

**visited로 재방문을 막아도 되는 이유**

BFS는 가까운 것부터 탐색하므로, 동일 단어는 **항상 최단 경로로 먼저 발견**된다.
어떤 경로로 도달하든 해당 단어에서 탐색 가능한 이웃은 동일하므로, 중복 방문을 막아도 최단 경로를 놓치지 않는다.

예를 들어 `abd`에 도달하는 두 가지 경로가 있다고 하면:
```
경로 A: abc → abd          (2단계) ← BFS가 먼저 발견
경로 B: abc → adc → abd   (3단계)
```
`abd`를 **처음 발견한 2단계가 곧 최단 경로**다.
어차피 `abd` 이후의 탐색 흐름은 두 경로 모두 동일하므로,
굳이 3단계로 다시 방문할 필요가 없다. visited로 막아도 무방한 이유가 여기에 있다. ⭐️
반대로 `abd`에서 이후 경로를 찾지 못한다면, 어떤 경로로 `abd`에 도달했든 결과는 동일하게 **경로 없음**이다.

---

### 3단계: 구현

```java
import java.util.*;

class Solution {
    public int solution(String begin, String target, String[] words) {
        int n = words.length;

        // 1. target이 words에 없으면 바로 return
        if (!Arrays.asList(words).contains(target)) return 0;

        // 2. BFS 준비
        Queue<int[]> queue = new ArrayDeque<>();
        boolean[] visited = new boolean[n];

        for (int i = 0; i < n; i++) {
            if (isPossible(begin, words[i])) {
                queue.offer(new int[]{1, i});
                visited[i] = true;
            }
        }

        // 3. BFS 탐색
        return bfs(queue, visited, words, target);
    }

    private int bfs(Queue<int[]> queue, boolean[] visited, String[] words, String target) {
        int n = words.length;

        while (!queue.isEmpty()) {
            int[] cur = queue.poll();
            int level = cur[0];
            int wordIdx = cur[1];

            if (target.equals(words[wordIdx])) {
                return level;
            }

            for (int i = 0; i < n; i++) {
                if (visited[i]) continue;

                if (isPossible(words[wordIdx], words[i])) {
                    queue.offer(new int[]{level + 1, i});
                    visited[i] = true;
                }
            }
        }

        return 0;
    }

    private boolean isPossible(String current, String target) {
        int diff = 0;
        for (int i = 0; i < current.length(); i++) {
            if (current.charAt(i) != target.charAt(i)) diff++;
        }
        return diff == 1;
    }
}
```

```
O(N² × L) = O(50 × 50 × 10) = O(25,000)
```

## 🚀 최적화: 와일드카드 패턴 + HashMap

### 아이디어

기존 풀이는 BFS에서 매번 모든 단어와 `isPossible()`을 호출해 `O(N)`의 탐색 비용이 발생했다.
대신 **BFS 전에 와일드카드 패턴으로 인접 리스트를 미리 구성**하면, BFS 탐색 시 `O(1)`로 인접 단어를 바로 조회할 수 있다.

```
"hot" → "*ot", "h*t", "ho*"
"dot" → "*ot", "d*t", "do*"

"*ot" 패턴을 공유 → 한 글자만 다른 단어!
```

### 최적화 코드

```java
import java.util.*;

class Solution {
    public int solution(String begin, String target, String[] words) {
        // 1. 전처리: 와일드카드 패턴으로 인접 리스트 구성
        Map<String, List<String>> graph = new HashMap<>();
        for (String word : words) {
            for (int i = 0; i < word.length(); i++) {
                String pattern = word.substring(0, i) + "*" + word.substring(i + 1);
                graph.computeIfAbsent(pattern, k -> new ArrayList<>()).add(word);
            }
        }

        // 2. BFS
        Queue<String[]> queue = new ArrayDeque<>();
        Set<String> visited = new HashSet<>();

        queue.offer(new String[]{begin, "0"});
        visited.add(begin);

        while (!queue.isEmpty()) {
            String[] cur = queue.poll();
            String word = cur[0];
            int level = Integer.parseInt(cur[1]);

            if (word.equals(target)) return level;

            for (int i = 0; i < word.length(); i++) {
                String pattern = word.substring(0, i) + "*" + word.substring(i + 1);

                for (String next : graph.getOrDefault(pattern, Collections.emptyList())) {
                    if (!visited.contains(next)) {
                        visited.add(next);
                        queue.offer(new String[]{next, String.valueOf(level + 1)});
                    }
                }
            }
        }

        return 0;
    }
}
```

### 시간복잡도 비교

`HashSet.contains()`는 평균 O(1)이지만, 문자열 해싱 시 길이만큼 연산이 필요하므로 정확히는 O(L)이다.

```
전처리: N개 단어 × L개 패턴 생성 × 패턴 길이 L → O(N × L²)
BFS:    N개 단어 × L개 패턴 조회 × contains O(L) → O(N × L²)
총합:   O(N × L²)
```

| | 기존 | 최적화 |
|---|---|---|
| 인접 단어 탐색 | `O(N × L)` | `O(L)` |
| 전체 BFS | `O(N² × L)` | `O(N × L²)` |
| visited | `boolean[]` | `HashSet` |

```
기존:   O(N² × L) = 50 × 50 × 10 = 25,000
최적화: O(N × L²) = 50 × 10 × 10 =  5,000
```

N이 크고 L이 작을수록 효과가 커지는 최적화다. 이 문제 범위에선 차이가 미미하지만, 단어 수가 수만 단위로 늘어나면 의미있는 차이가 발생한다.

## 💁🏻 회고

**BFS가 최단경로를 보장하는 이유**
- 큐(FIFO)를 사용하므로 **단계 수가 작은 것이 항상 먼저 처리**됨
- target을 처음 발견한 순간이 곧 최단 경로 → 즉시 return 가능 ⭐️
