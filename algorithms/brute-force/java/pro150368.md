## ⚙️ 사용한 알고리즘
- **완전탐색 (Brute Force)**: 모든 이모티콘 할인율 조합 시도
- **DFS (깊이 우선 탐색)**: 이모티콘마다 할인율을 순서대로 결정하는 재귀 탐색
- **시뮬레이션 (Simulation)**: 각 조합에 대해 유저 전체의 구매/가입 행동 계산

## 💡 풀이 과정 (생각의 흐름)

### 1단계: 문제 분석 및 완전탐색 가능 여부 판단

**핵심 결정 사항 파악**
> 우리가 선택해야 하는 것: **m개의 이모티콘 각각에 어떤 할인율(10/20/30/40%)을 적용할 것인가**

**조합의 수 계산**
```
이모티콘 최대 7개, 할인율 4가지
→ 가능한 조합 수: 4^7 = 16,384가지
```

**시간복잡도 검증**
```
16,384 (조합) × 100 (유저) × 7 (이모티콘) = 약 11,468,800회
→ 1억 미만 ✅ → 완전탐색으로 충분히 가능
```
> Java 기준 1억 연산 ≈ 약 1초. 약 1,147만 회는 여유롭게 통과 가능.

---

### 2단계: 알고리즘 설계

**DFS 구조 설계**

이모티콘마다 순서대로 할인율을 결정하는 구조 → DFS와 일치

```
dfs(idx = 0) → 0번 이모티콘 할인율 결정
  dfs(idx = 1) → 1번 이모티콘 할인율 결정
    dfs(idx = 2) → 2번 이모티콘 할인율 결정
      ...
        dfs(idx = m) → 모든 할인율 확정 → 시뮬레이션 실행
```

탐색 순서 예시 (이모티콘 3개):
```
[10, 10, 10] → [10, 10, 20] → [10, 10, 30] → [10, 10, 40]
→ [10, 20, 10] → [10, 20, 20] → ...
```
마지막 이모티콘부터 가장 빠르게 변화 (숫자 올림 방식과 동일한 패턴)

**유저 시뮬레이션 로직 설계**
```
유저 한 명 처리:
  1단계: 이모티콘 전체 순회
  2단계: 이모티콘 할인율 >= 유저 기준 할인율 이면 → 구매액 누적
  3단계: 총 구매액 >= 유저 기준 가격 이면 → 가입 처리
         아니면 → 판매액에 추가
```

**결과 비교 로직 설계**

우선순위: 가입자 수 > 판매액
```java
if (newSubscribe > bestSubscribe) {
    // 가입자 수가 더 많으면 무조건 갱신
} else if (newSubscribe == bestSubscribe && newSales > bestSales) {
    // 가입자 수 같을 때만 판매액 비교
}
```
> ⚠️ 주의: `newSubscribe > bestSubscribe`일 때 `bestSales`도 함께 갱신해야 한다.  
> 가입자 수가 늘었을 때 이전 bestSales를 그대로 유지하면 잘못된 값이 남는다.

### 3단계: 구현

```java
import java.util.*;

class Solution {
    int[] discounts;
    int[][] users;
    int[] emoticons;
    int bestSubscribe = 0;
    int bestSales = 0;

    public int[] solution(int[][] users, int[] emoticons) {
        this.users = users;
        this.emoticons = emoticons;
        this.discounts = new int[emoticons.length];

        dfs(0);

        return new int[]{bestSubscribe, bestSales};
    }

    private void dfs(int idx) {
        if (idx == emoticons.length) {
            int newSubscribe = 0;
            int newSales = 0;

            for (int[] user : users) {
                int sales = 0;
                int discountMin = user[0];
                int subscribeLimit = user[1];

                for (int i = 0; i < emoticons.length; i++) {
                    if (discounts[i] >= discountMin) {
                        sales += emoticons[i] * (100 - discounts[i]) / 100;
                    }
                }

                if (sales >= subscribeLimit) {
                    newSubscribe += 1;
                } else {
                    newSales += sales;
                }
            }

            if (newSubscribe > bestSubscribe) {
                bestSubscribe = newSubscribe;
                bestSales = newSales;       // bestSales도 함께 갱신!
            } else if (newSubscribe == bestSubscribe && newSales > bestSales) {
                bestSales = newSales;
            }

            return;
        }

        for (int discount : new int[]{10, 20, 30, 40}) {
            discounts[idx] = discount;
            dfs(idx + 1);
        }
    }
}
```

## 📊 총 시간복잡도
```
4^m × n × m
= 4^7 × 100 × 7
≈ 11,468,800 연산
→ O(4^m × n × m)
```

## 💁🏻 회고

**클래스 필드 vs 지역 변수**
- DFS 재귀 함수에서 공유 상태(`discounts`, `users`, `emoticons`)가 필요할 경우 클래스 필드로 선언해야 접근 가능
- `solution()` 내 지역 변수는 `dfs()` 메서드에서 직접 참조 불가

**`discounts[]` 배열 공유 방식 이해**
- DFS에서 `discounts[idx] = discount`로 값을 덮어쓰면서 내려감
- base case 도달 시 `discounts[0..m-1]`에 해당 경로의 할인율 조합이 담겨 있음
- 별도 복사 없이 하나의 배열을 재사용하는 것이 핵심

**`Arrays.asList()` vs `new int[]{}` 주의**
```java
// ❌ 박싱/언박싱 비용 발생 (Integer 리스트 생성)
for (int discount : Arrays.asList(10, 20, 30, 40))

// ✅ 기본형 배열 직접 사용 권장
for (int discount : new int[]{10, 20, 30, 40})
```
> 이 문제 규모에서는 차이 없지만, 코딩테스트에서는 기본형 배열 사용을 습관화하자.

**bestSales 갱신 타이밍 주의**
- 가입자 수가 갱신될 때 `bestSales`도 반드시 새 값으로 교체해야 함
- 이전 가입자 수 기준의 `bestSales`를 그대로 두면 비교 기준이 오염됨
